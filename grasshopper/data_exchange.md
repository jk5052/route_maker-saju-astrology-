# Grasshopper 데이터와 Python 반복 실험 연결

상태: 연결 설계. 실제 수업 파일과 지표 정의를 확인하기 전이며, 연결 구현·실제 데이터 재실험 완료를 뜻하지 않는다.

사용자가 보유한 Williamsburg 수업 자료를 우선 사용한다.
Grasshopper는 거리·지표 작성과 최종 렌더링을 맡고, Python은 사주·점성술 계산과 반복 경로 실험을 맡는다.
새 OSM 수집이나 속성 재계산은 원본에서 실제로 빠진 항목을 확인한 뒤 결정한다.

## 먼저 확인할 원본

- `.gh` / `.ghx`, 연결된 `.3dm` 및 외부 입력 파일의 위치와 서로 대응하는 버전.
- 실제 거리 지표의 이름·정의·단위·값 범위·좋은 방향·결측 처리·집계 단위.
  지표가 6개라는 내용은 사용자 설명에 따른 잠정 정보이며 아직 파일로 확인하지 않았다.
- 지표가 전체 거리 구간마다 있는지, 장소점·격자셀·선택한 경로에만 있는지.
  이미 선택된 경로만 있으면 다른 경로를 찾는 실험에 쓸 전체 그래프가 추가로 필요하다.
- 곡선과 지표를 연결하는 구간 ID 또는 Grasshopper 데이터 트리의 대응 관계.
- Rhino 모델 단위, 실제 지리 좌표계 유무, 모델 이동·회전·스케일 이력.
- 사용할 출발·도착점. 기존 합성 격자 끝점을 그대로 사용하지 않는다.

## 최소 연결: 그래프와 지표를 내보내고 구간 ID를 돌려받기

반복 경로 계산에는 구간의 연결 관계, 실제 길이, 지표값이 필요하다.
원본 곡선은 Rhino에 두고 Python의 결과 ID로 다시 선택할 수 있다.
그러면 최종 렌더링용 곡선을 다시 근사하거나 지리 좌표로 변환하지 않아도 된다.

다음은 원본 확인 후 맞출 **제안 교환 규격**이다. 아래 파일들은 아직 생성하지 않았다.

| 파일 | 필수 내용 | 쓰임 |
|---|---|---|
| `segments.csv` | `segment_id`, `u`, `v`, `length_m`, `direction`, 실제 지표 열 | Python 경로 계산 |
| `nodes.csv` | `node_id`, `x`, `y`, 필요 시 `z` | 로컬 좌표로 끝점 선택·스냅 및 연결 검토 |
| `metadata.json` | 데이터 버전, 파일 해시, 좌표·길이 단위, 지표 정의·정규화 기준 | 입력 의미와 재현 조건 고정 |
| Python 결과 `routes.json` | 날짜, 체계, 데이터 버전, 순서 있는 `segment_id`, 구간별 진행 방향, 길이 | Rhino에서 원본 곡선 선택·정렬 |

`u`와 `v`는 실제 접속점의 식별자다. 같은 위치에서 교차해 보여도 접속하지 않는 고가·지하 구간은 다른 노드로 남긴다.
평행 간선은 별도 `segment_id`로 구별한다. `direction`은 `both`, `u_to_v`, `v_to_u`처럼 의미를 고정한다.
`length_m`는 원본 곡선의 실제 길이를 단위 변환한 값이며, 양 끝점의 직선거리로 대체하지 않는다.

Rhino 원본 곡선에도 동일한 `segment_id`를 보존해야 한다. 내보내기 후 리스트를 재정렬해도 ID는 바뀌지 않아야 한다.
Grasshopper 트리를 각각 Flatten한 뒤 행 순서만으로 곡선과 점수를 연결하지 않는다.
구간별 지표가 정확히 대응하는 상태에서 함께 내보낸다.

Python의 결과는 연결 가능한 순서와 방향을 포함한다. Rhino에서는 해당 ID의 원본 곡선을 찾아 필요 시 방향을 뒤집고,
결합 경로·단독 경로·최단 경로를 각 레이어로 그린다. 결과와 원본의 데이터 버전이 다르면 섞어 쓰지 않는다.

## 경험 성질과 실제 거리 지표의 연결

현재 경험 성질 Q는 `activation`, `receptivity`, `clarity`, `expansion`, `grounding`, `flow`의 6축이다.
이것은 수업에서 측정한 거리 지표가 6개라는 말과 다른 분류다.

실제 거리 지표가 k개라면 변환 행렬은 **경험 성질 6개 × 측정 지표 k개**로 작성한다.
정확히 6개면 6×6이지만, 두 축의 수가 같다는 이유로 항등 행렬이나 일대일 대응을 쓰지는 않는다.

```text
C[q] = 기존 사주·점성술 결합 점수
u[j] = Σq C[q] × M_actual[q,j]
w[j] = u[j] / Σj u[j]
luck(segment) = Σj w[j] × normalized_metric(segment,j)
```

현재 8개 이름에 실제 지표를 억지로 끼우거나 존재하지 않는 지표를 0으로 채우지 않는다.
각 실제 지표의 의미를 확인한 뒤 경험 성질과 연결하고, 계수는 초기 설계값으로 표시한다.
정규화 방식도 고정한다. 예를 들어 값이 클수록 불리한 지표는 유리한 방향으로 변환할지 명시하고,
물리적 0과 결측을 구별한다. 새 행렬의 수치는 원본 지표 확인 전에는 정하지 않는다.

## 좌표 처리

Python 경로 계산 자체에 위경도는 필수 조건이 아니다. 명시적인 노드·간선 ID와 미터 단위 길이를 사용하면
모델 좌표를 그대로 보존한 채 계산하고 결과 ID만 Rhino로 돌려줄 수 있다.
모델 좌표를 끝점 스냅에 쓸 때는 입력 점과 노드 좌표가 같은 좌표계·단위여야 한다.

Rhino 문서의 단위와 EPSG 코드만으로 이동·회전된 로컬 모델을 지리 좌표에 복원할 수는 없다.
지도에 올릴 필요가 있으면 원본 CRS와 모델 변환 이력 또는 기준점을 확보한 뒤 변환한다.
`.3dm`의 모델 단위는 [File3dmSettings.ModelUnitSystem](https://developer.rhino3d.com/api/rhinocommon/rhino.fileio.file3dmsettings/modelunitsystem)에서 확인할 수 있으나,
그 값만으로 지리 기준점까지 확인되는 것은 아니다.

**표준 GeoJSON을 선택하면 WGS84 경도·위도 좌표로 내보낸다.**
로컬 피트·미터 좌표를 그대로 넣고 표준 GeoJSON으로 취급하지 않는다.
[GeoJSON RFC 7946, 좌표계 규정](https://www.rfc-editor.org/rfc/rfc7946.html#section-4)
로컬 좌표로 실험하고 Rhino에서 렌더링하는 단계는 CSV와 메타데이터로 연결하고,
웹 지도가 필요한 단계에만 WGS84 GeoJSON 출력을 추가할 수 있다.

## 저장소에서 수정할 부분

| 현재 코드 | 확인한 결합 지점 | 원본 확인 후 작업 |
|---|---|---|
| `engine/combine_reading.py` | 경험 성질 계산과 기본 6×8 행렬 읽기 | 경험 성질 계산을 재사용하고 실제 지표 행렬을 별도 입력으로 주입 |
| `grasshopper/lucky_route_ghpython.py` | 속성 8종 상수, 결측 0 대입, 좌표를 노드 키로 사용 | 실제 지표 목록·명시적 노드 ID를 받는 로더/그래프 연결 계층 추가 |
| `analysis/route_sensitivity.py` | 합성 데이터 경로·끝점·행렬이 고정돼 있음 | 실제 데이터·행렬·끝점·단위를 입력으로 받아 같은 60일 실험 실행 |
| `grasshopper/` | 기존 예제는 Python 결과를 경위도 점으로 출력 | 결과 구간 ID와 순서로 원본 곡선을 선택하는 입력 컴포넌트 추가 |
| `web/mapbox-prototype/app.js` | 경위도와 기존 속성 표시를 가정 | 웹 출력이 필요할 때 좌표 변환과 실제 지표 표시를 맞춤 |

사주·점성술 계산 규칙, 0.5:0.5 결합 방식, 민감도 실험 계수는 데이터 연결과 분리해서 유지한다.
기본 연결을 먼저 검증하고 실제 데이터에서 얻은 결과로 민감도 변경을 다시 판단한다.

## 연결 검증 순서

1. 모든 구간 ID의 유일성, 노드 참조, 곡선 길이, 지표 대응과 결측을 검사한다.
2. 작은 표본 경로에서 GH와 Python의 동일 비용식·동일 끝점 결과를 비교한다.
   동률 최적 경로가 있으면 구간 목록뿐 아니라 비용도 비교한다.
3. Python 경로 ID를 Rhino에 돌려주어 원본 곡선과 위치·길이·진행 방향이 맞는지 확인한다.
4. 같은 원본 스냅샷으로 60일을 다시 실행하고 경로 수·단독 체계 분기일·가중치 분산·우회 거리를 보고한다.

현재 저장소에서는 수업 원본이나 실제 6개 거리 지표 테이블을 찾지 못했다.
실제 파일 경로와 내용이 확인되면 위 제안을 그 데이터 구조에 맞춰 확정한다.
