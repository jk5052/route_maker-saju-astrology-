# Williamsburg 실제 보행망·거리 속성 전환 범위

검토일: 2026-09-30. 이 문서는 작업 범위이며 실제 네트워크 교체를 실행한 결과가 아니다.
현재 [60일 분석](report.md)의 합성 격자 결과와 구별한다.

## 후속 방향: 기존 Grasshopper 자료 우선

사용자가 실제 Williamsburg 수업 자료를 이미 보유하고 있다고 설명했다.
따라서 우선 작업은 **기존 거리 구간·지표를 내보내 Python 실험과 연결하는 것**으로 수정한다.
Grasshopper는 데이터 작성과 렌더링을, Python은 일일 가중치와 반복 경로 계산을 맡는다.
구체적인 교환 규격과 코드 연결 지점은 [Grasshopper 데이터 연결 설계](../../grasshopper/data_exchange.md)에 정리했다.

아래의 원자료 부재는 **현재 저장소 안에서 확인한 상태**다. 저장소 밖의 수업 자료도 없다는 뜻이 아니다.
6개 지표의 실제 이름·정의·완성 범위와 원본 파일 위치는 아직 확인하지 못했다.
아래 OSM 수집·속성 생성 항목은 기존 자료를 점검한 뒤 **부족한 부분이 있을 때 적용할 보완 범위**로 읽는다.
기존 자료가 충분하면 새 네트워크나 지표를 만들 필요가 없다.

장소 수집 코드의 범위는 위도 `40.708–40.722`, 경도 `-73.970–-73.950`다.
현재 두 끝점은 모두 이 범위 밖이다. 그대로 최근접 노드를 찾으면 지역 경계 쪽으로 잘못 붙을 수 있으므로,
전환 시 끝점을 새로 정하고 허용 스냅 거리도 명시해야 한다.
이 사각형은 현재 프로젝트의 분석 범위이며 Williamsburg의 공식 경계라고 주장하지 않는다.

## 1. 보행 네트워크와 구간 식별자: 기존 자료 점검 후 필요한 경우 보완

분석 경계를 확정하고 외곽 여유 구역을 포함해 `graph_from_polygon(..., network_type="walk")`로 수집한다.
경계에서 잘린 길 때문에 우회가 사라지지 않도록 수집 범위와 평가 범위를 구분한다.
OSMnx는 보행망 수집, 투영, 최근접 노드·간선 검색, GraphML 저장을 제공한다.
그래프의 간선은 `(u, v, key)`로 구분하며 평행 간선을 유지한다.
[OSMnx 공식 API 문서](https://osmnx.readthedocs.io/en/stable/user-reference.html)

필요한 구현 작업:

1. 버전·수집일·경계·필터·원본 스냅샷을 고정하고 GraphML과 노드/간선 공간 파일을 저장한다.
2. 원본 OSM 노드 식별자를 연결 기준으로 유지한다. 현재 라우터의 좌표 6자리 반올림만으로 그래프를 재구성하면
   입체 교차로나 같은 좌표의 다른 층을 잘못 연결할 수 있다.
3. 보행 가능 여부, 계단, 횡단, 접근 제한, 교량·터널, 공원 입구와 단절 구간을 확인한다.
   일반 보행망과 계단을 피하는 경로는 별도 조건이며, 현재 연구 범위에서 어느 쪽을 다룰지 명시한다.
4. 길이·버퍼·거리 집계는 미터 단위의 지역 투영 좌표계에서 수행한다. 웹 출력만 경위도로 변환한다.
5. OSMnx의 단순화된 굴곡 선형과 길이를 보존한다. 세그먼트를 추가로 나누면 새 노드와 부모 간선 ID를 기록하고
   길이와 속성의 집계 방식도 다시 계산한다.
6. 출발·도착점을 네트워크에 붙인다. 첫 MVP는 거리 제한을 둔 최근접 노드 방식으로 시작하고,
   길 중간의 실제 위치를 지원하려면 최근접 간선 위에 점을 투영한 뒤 간선을 분할한다.
   `nearest_edges`는 간선 탐색 기능이며 이 분할까지 자동으로 대신하는 것은 아니다.

**산출물 제안:** `data/raw/osm/williamsburg.graphml`, `data/processed/walk_nodes.gpkg`,
`walk_edges.gpkg`, 원본 간선과 `segment_id`의 대응표, 데이터 명세 JSON.
이 경로들은 앞으로 만들 파일이며 현재 생성된 산출물이 아니다.

## 2. 거리 속성 8종을 만드는 작업

다음은 데이터로부터 거리 속성을 구성하기 위한 설계안이다. 원자료가 그대로 경험적 성질의 참값이라는 뜻은 아니다.
모든 속성에서 원자료 단위, 공간 집계 거리, 변환식, 결측 상태, 자료 기준일을 함께 저장한다.

| 거리 속성 | 원자료 후보 | 구간 속성으로 만드는 작업 | 확인해야 할 한계 |
|---|---|---|---|
| green | 가로수 위치, 공원 경계, 수관 자료 | 일정 길이당 가로수 수, 구간 주변 식생·공원 비율을 집계 | 수목 개수가 보행자가 보는 녹시율과 같지는 않음 |
| water | 해안선, 수변 공개공간, 접근 가능한 입구 | 실제 접근 거리와 수변에 노출된 구간 비율을 구분 | 강과 가까워도 담장·사유지로 접근이나 시야가 막힐 수 있음 |
| sunlight | 건물 외곽선·높이, 대상 날짜·시각, 태양 위치 | 보행 구간 표본점의 그림자를 계산해 일조 비율 생성 | 날짜·시각에 따라 바뀜. 단순 건물 밀도를 일조로 명명하지 않음 |
| open_sky | 건물 외곽선·높이, 필요 시 수관 | 거리 폭·높이에 따른 개방감 대리지표 또는 sky-view 계산 | sunlight와 같은 값으로 채우지 않음. 입체 공간 계산 또는 현장 대조 필요 |
| quiet | 도로 종류·차로, 교통 자료, 가능하면 시간대별 현장 소음 | 교통 노출의 역방향 대리지표부터 시작하고 측정값과 대조 | 차량 정보나 민원 빈도는 데시벨 측정값이 아님 |
| vibrant | 기존 장소 유형·social_component, 입구 위치, 영업 상태 | 보행 구간 주변 장소 밀도와 거리 감쇠 점수 집계 | 현재 CSV에는 영업시간·보행 유동량이 없음. 실제 활기로 표현하려면 보완 필요 |
| rest | DOT 좌석, 공원 벤치, OSM 벤치·쉼터 | 접근 가능한 좌석 수와 가까운 좌석까지의 보행 거리 | 상업시설에 머물 수 있다는 점수와 무료 공공 좌석을 구별 |
| culture | 문화시설·도서관·갤러리·박물관·공연장 유형 | 접근 가능한 문화시설 수·거리·유형을 집계 | 기존 access_component를 문화 점수로 그대로 사용하지 않음 |

확인한 공공 자료:

- [NYC Parks 2015 Street Tree Census](https://data.cityofnewyork.us/Environment/2015-Street-Tree-Census-Tree-Data/uvpi-gqnh/about_data)는
  특정 시점의 가로수 조사다. 현재성 검토와 공원 자료 보완이 필요하다.
- [NYC Waterfront Public Access Areas](https://data.cityofnewyork.us/Recreation/Waterfront-Public-Access-Areas-WPAAs-Map/jakx-zd39)는
  공개 수변공간을 식별하는 후보 자료다. [Waterfront Access Map](https://www.nyc.gov/assets/planning/pages/waterfront-access-map/index.html)과 대조한다.
- [NYC 건물 외곽선 메타데이터](https://github.com/CityOfNewYork/nyc-geo-metadata/blob/main/Metadata/Metadata_BuildingFootprints.md)는
  건물 외곽선, 지면 표고, 지면 기준 지붕 높이 등의 필드를 설명한다. 높이의 0 또는 NULL이 미확인 값을 의미할 수 있으므로
  이를 높이 0m로 계산하지 않는다. 좌표·높이의 단위도 가져온 배포본에서 확인한다.
- [NYC DOT Seating](https://www.nyc.gov/html/dot/html/pedestrians/seating.shtml)은 벤치와 기대는 좌석의 위치 자료를 연결한다.
- [NYC Facilities Database](https://data.cityofnewyork.us/City-Government/Facilities-Database-Shapefile/2fpa-bnsx)는
  도서관·문화시설 분류와 위치를 보완할 후보 자료다. 기존 장소 목록과 중복을 제거한다.

`social_component`와 `access_component`는 이미 설계된 **장소 단위** 점수다.
이를 구간 점수로 만들려면 장소가 어느 길에서 접근 가능한지와 집계 범위를 별도로 정해야 한다.
단순 직선 버퍼만 쓰면 물 건너편·벽 뒤·고가도로 위의 장소가 잘못 기여할 수 있다.
현재 장소 수집의 잔여 포화 파일도 검토해, 데이터가 적은 구역과 실제로 장소가 적은 구역을 구별한다.

## 3. 정규화·결측·시간 조건

- 속성별 원시 값과 0–1 변환 값을 둘 다 저장한다. 변환 기준은 고정된 평가 지역·스냅샷에 맞춰 정의한다.
  선택한 경로나 매일의 데이터만으로 min–max를 다시 계산하면 날짜 간 비교 기준이 달라진다.
- 결측을 자동으로 0점 처리하지 않는다. 특히 현재 `load_segments`의 `props.get(q, 0.0)`은 실제 자료 전환 때
  검증 단계로 보완해야 한다. 결측으로 인한 제외·추정·중립값 중 선택한 정책과 해당 구간을 기록한다.
- 정적 속성(건물, 공원)과 시간 속성(일조, 영업, 소음)을 분리한다. 우선 고정된 산책 시각과 정적 스냅샷으로 비교하고,
  동적 자료를 추가하면 날짜별 거리 속성을 다시 계산한다.
- 날짜별 경로가 바뀌는 원인을 구분하기 위해 먼저 거리를 고정한 60일 실험을 실행하고,
  그다음 일조·영업 등 시간 변화까지 포함한 실험을 별도로 실행한다.

**산출물 제안:** `street_attribute_definitions.md`, 구간별 원자료 테이블,
0–1 거리 속성 8종, `source_date`, `source_id`, 속성별 결측·추정 상태.

## 4. 기존 라우터·웹과 연결

현재 규칙 해석과 `quality_street_matrix.csv`를 바로 바꿀 필요는 없다.
실제 그래프를 입력하는 계층과 거리 속성 생성 계층을 먼저 구축한다.

- 원본 `(u,v,key)` 연결 정보를 유지하는 NetworkX/OSMnx 기반 라우터를 연결하거나,
  기존 라우터를 명시적인 노드·간선 ID를 받도록 수정한다. 모든 길을 좌표만 보고 무방향으로 묶는 방식은 재검토한다.
- 출발 방향에 맞게 굴곡 있는 간선 좌표 순서를 정렬해 GeoJSON을 출력한다.
- 웹의 초기 지도 범위, 출발·도착점, 출력 경로, 실제 수집 데이터의 출처 표시를 갱신한다.
- 비용 양수 조건, 끊긴 출발·도착점, 너무 먼 스냅, 접근 불가 구간을 명시적으로 처리한다.
  민감도 계수는 실제 자료에서 우회 거리와 경로 품질을 평가한 뒤 선택한다.

## 5. 검증과 완료 기준

| 검증 | 완료 시 확인할 결과 |
|---|---|
| 네트워크 | 경계·공원 입구·수변·교량 등 표본 구간이 실제로 연결되고 불가능한 횡단이 없음 |
| 거리·식별자 | 미터 단위 길이, 중복 없는 구간 ID, 평행 간선 구분, 원본 추적 가능 |
| 속성 | 8개 속성의 분포·결측률·극단값을 지도에서 검토하고 서로 다른 환경의 표본을 현장/사진과 대조 |
| 경로 | Williamsburg 내 여러 출발·도착점에서 연결성, 최단 길이, 우회 길이, 겹침 비율 확인 |
| 민감도 | 같은 60일·같은 끝점으로 기본/희소화/중심화/계수 실험을 재실행하고 여러 끝점에서도 비교 |
| 해석 | 서로 다른 경로 수뿐 아니라 어떤 속성 때문에 바뀌었는지, 사용자에게 의미 있는 차이인지 확인 |
| 재현 | 원본 버전·수집일·파라미터·환경·변환식·검증 기록으로 같은 산출물 재생성 가능 |

우선 순서는 **수업 원본·실제 지표·좌표 확인 → 구간 ID를 보존한 내보내기 → 실제 지표용 변환 행렬과 로더 연결
→ 60일 재비교 → 경로 ID로 Rhino 원본 곡선 렌더링**이다.
기존 자료가 부족한 경우에만 위의 수집·속성 계산을 추가한다.
그 경우에는 sunlight/open_sky의 공간 계산, 장소에서 구간으로의 접근성 집계,
quiet의 대리지표 검증이 큰 작업이 될 수 있다. 실제 지표가 다르면 이 8개 목록도 그대로 요구하지 않는다.
